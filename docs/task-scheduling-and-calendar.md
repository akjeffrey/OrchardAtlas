# Task dates, reminders and Google Calendar

All task targets share a start date (default today for new tasks), an optional inclusive end date, and up to ten reminders at 9 AM local time. Enter offsets in days or weeks, including zero for the start date, up to 365 days before start. Remove reminders individually. Repeating tasks retain their anchor and repeat the range duration; completed history is unchanged. Existing `dueDate` values become start dates without migration; undated legacy tasks remain valid. `endDate` is optional in task and plan documents. Dates and reminder offsets persist in offline storage and Drive backups.

The existing native notification channels request permission on saving reminders. Android uses inexact alarms that survive restart/update; battery policy can delay delivery. iOS uses local notifications. A rolling 366-day projection supplies the earliest 60 future reminders per orchard, refreshed while open and on launch; regularly reopen the app to refresh it. Past reminders are not replayed. Completing work removes pending reminders on the next refresh; group reminders are aggregated by occurrence. Notification permission and calendar permission are independent.

## Phone setup

In Android Settings, add the Google account and enable Calendar synchronization. Open OrchardAtlas Settings → Task calendar sync → Choose calendar / refresh access, grant Calendar permission, and choose the Google account calendar. On iOS, add the Google account under Calendar accounts and grant full Calendar access. No Google API keys, OAuth client secrets, or service account are required. A local/device calendar can also be chosen but will not upload to Google.

Calendar sync is optional, per user/orchard/device, and one-way. The app exports dated tasks as all-day events, translating the inclusive end to the calendar provider's exclusive end. Group tasks create one event per occurrence with completion counts. Empty matching groups remain valid and receive an event. Recurrences are projected 90 days ahead. Task names and notes are sent to the chosen calendar and inherit its sharing permissions. Local reminders remain app notifications; calendar alerts are not added automatically. Editing events in Calendar does not edit tasks. Change task definitions and status inside OrchardAtlas.

The application worker reconciles after edits with a short debounce, every minute while open, and on launch. Native calendar adapters upload asynchronously when the device is online; no guarantee is made about Google's upload timing. Task edits remain local/offline when calendar access fails, and sync retries on the next refresh. Settings reports sync failures. Calendar selection and provider identifiers are device-specific and intentionally excluded from Drive backups; reconnect on a restored/new phone.

Repository interfaces separate Flutter UI/domain from device calendars. Android uses CalendarContract with runtime READ/WRITE_CALENDAR permissions; iOS uses EventKit and usage descriptions. Only saved, marked OrchardAtlas events for the selected orchard are updated or removed. Event identifiers and recovery markers prevent duplicate exports after interrupted saves. Other personal calendar events are untouched. Disconnect or change calendars to remove that orchard's generated events. Revoked permissions must be restored before cleanup. Disconnect before uninstalling if exported calendar events should be removed; uninstall cannot run cleanup code.

## Validation

Domain tests cover date ordering, inclusive ranges, recurring range expansion, completion history, reminder offsets and legacy migration, unique notification IDs, past/completed suppression, grouped calendar entries, UTC calendar mapping and repository serialization. Firestore emulator tests cover date ranges, completed history and bounded reminder lists. CI also compiles Android and iOS. Device acceptance: connect an actual Google calendar, create/edit a range and grouped task, complete a member, verify one corresponding event updates in Google Calendar, toggle offline, relaunch, test notification permission denial, and disconnect. These external-account/device checks require a real configured phone.
